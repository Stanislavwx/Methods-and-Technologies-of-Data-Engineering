# Лабораторна робота №6: Побудова ETL-конвеєра на основі веб-даних та API

Проєкт присвячено розробці наскрізного ETL-конвеєра (Extract, Transform, Load) для збору даних про товари з відкритого веб-сайту, їх інтеграції з фінансовими валютними курсами Національного банку України (НБУ), збереження у форматах CSV та Apache Parquet, проведення порівняльного бенчмаркінгу та формування BI-аналітики.

**Дисципліна:** Методи та технології інженерії даних  
**Студент:** Чепара Станіслав (група ФеП-32)  
**Джерела даних:** Веб-каталог книг [books.toscrape.com](http://books.toscrape.com/) + Відкритий REST API [НБУ](https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json)

## 🎯 Мета роботи

Опанувати практичні навички отримання даних із різнорідних джерел (веб-скрапінг та REST API), їх перетворення, нормалізації та інтеграції, побудови автоматизованого ETL-конвеєра, використання колонкового формату Parquet для збереження аналітичних даних та розрахунку ключових бізнес-метрик.

## 🏗 Архітектура ETL-конвеєра

```text
       books.toscrape.com (HTML)               API НБУ (JSON)
                   │                                  │
                   ▼                                  ▼
      [EXTRACT] BeautifulSoup                [EXTRACT] requests
                   │                                  │
                   ▼                                  ▼
          raw/products.csv                raw/exchange_rates.json
                   │                                  │
                   └─────────────────┬────────────────┘
                                     ▼
                        [TRANSFORM & INTEGRATION]
                  • Видалення дублікатів (0 виявлено)
                  • Контроль пропусків (0 пропусків)
                  • Стандартизація типів (float64, datetime64)
                  • Мультивалютний перерахунок: GBP → UAH → USD, EUR
                  • Валідація зворотної похибки (< 0.25 грн)
                                     │
                                     ▼
                                  [LOAD]
                 ┌───────────────────┴───────────────────┐
                 ▼                                       ▼
    processed/products_processed.csv    processed/products_processed.parquet
                 └───────────────────┬───────────────────┘
                                     ▼
                         [BI-АНАЛІТИКА ТА ГРАФІКИ]
                  • 5 підсумкових таблиць показників
                  • Рис. 1: Середні та медіанні ціни
                  • Рис. 2: Структура сегментів та боксплоти
                  • Рис. 3: Діапазони екстремумів (Min-Mean-Max)
```

## 📊 Порівняння форматів зберігання: CSV vs Parquet

Підготовлений набір із 302 записів та 12 колонок експортовано у двох форматах. За результатами повторного завантаження (100 ітерацій):

| Критерій оцінки | CSV (`products_processed.csv`) | Parquet (`products_processed.parquet`) | Різниця / Висновок |
|:---|:---:|:---:|:---|
| **Розмір на диску** | **37.81 КБ** (38 717 байт) | **23.35 КБ** (23 907 байт) | **Parquet на 38.3% компактніший** (стиснення 1.62x) |
| **Збереження типів даних** | Втрата типів (`scraped_at` читається як `str`) | **Повне збереження схеми** (`datetime64[us]`, `float64`) | Parquet усуває потребу повторного приведення типів |
| **Час читання (100 ітер.)** | 2.84 мс | 4.51 мс | На мікро-файлах CSV швидший через фіксований оверхед метаданих Parquet |
| **Структура зберігання** | Рядкова (Row-oriented) | Колонкова (Column-oriented) | Parquet оптимізований для OLAP та селективних вибірок |
