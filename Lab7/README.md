# Лабораторна робота №7: Інкрементальна обробка та відстеження змін у даних

Проєкт присвячено реалізації інкрементального конвеєра обробки даних (Incremental Processing) транзакцій інтернет-магазину: розподілу даних на неперетинні часові пакети, послідовній обробці нових порцій (Initial Load, `INSERT`, `UPDATE`), веденню журналу аудиту (`processing.log`) та верифікації результатів шляхом зіставлення з повною пакетною обробкою (`customers_full`).

## 🎯 Мета роботи

Опанувати практичні навички інкрементальної обробки даних:
1. Поділу транзакційного масиву на часові пакети без взаємного перетину за датами.
2. Початкового завантаження (Initial Load) першого пакета та формування базового стану таблиці клієнтів `customers_current.csv`.
3. Інкрементальної обробки нових пакетів з виявленням нових покупців (`INSERT`) та модифікацією показників існуючих (`UPDATE`).
4. Автоматизованого аудиту та протоколювання метрик у файл `processing.log`.
5. Контрольної повної обробки датасету (`customers_full`) та 100% математичної верифікації інкрементального пайплайну.
6. Порівняльного аналізу ефективності Full vs Incremental Processing.

## 🏗 Схема інкрементального конвеєра

```text
Вхідний масив (data_student_rfm1.csv)
  └──> Первинне очищення (56 726 транзакцій, 3 992 клієнти)
        └──> Поділ на 3 часові пакети
              │
              ├──> transactions_period_1.csv (13 752 транз.)
              │       └──> [Initial Load] ──> customers_current.csv (стан 1: 1 917 клієнтів)
              │
              ├──> transactions_period_2.csv (15 688 транз.)
              │       └──> [Incremental] ──> INSERT (957) + UPDATE (1 137) ──> стан 2 (2 874 клієнти)
              │
              └──> transactions_period_3.csv (27 286 транз.)
                      └──> [Incremental] ──> INSERT (1 118) + UPDATE (1 726) ──> фінал (3 992 клієнти)
                                              │
                      ┌───────────────────────┴───────────────────────┐
                      ▼                                               ▼
         customers_incremental.csv                         customers_full.csv
                      └───────────────────────┬───────────────────────┘
                                              ▼
                             [Верифікація: 100% тотожність]
```

## 💡 Чому інкрементальна обробка ефективніша за повну?

1. **Зниження I/O-навантаження:** У Full Processing кожен новий пакет змушує систему повторно перечитувати весь накопичений обсяг з диска (для 3 пакетів: $13\,752 + 29\,440 + 56\,726 = 99\,918$ рядків). У Incremental Processing зчитується тільки дельта ($56\,726$ рядків), що вже на трьох періодах скорочує обсяг сканування на **43.2%**.
2. **Масштабованість $O(N)$ проти $O(N^2)$:** При щоденному надходженні даних Full Processing демонструє квадратичне накопичувальне зростання обчислень ($O(N^2)$). Incremental Processing масштабується лінійно ($O(N)$), що унеможливлює зрив часового вікна завантаження (ingestion window).
3. **Низька затримка (Low Latency):** Інкрементальний конвеєр дозволяє бізнес-аналітиці отримувати оновлені вітрини за лічені секунди (near real-time).
